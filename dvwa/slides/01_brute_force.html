🔓 Brute Force Attack

Comprendere, sfruttare e mitigare gli attacchi di forza bruta contro i sistemi di autenticazione

📖 Cos'è un Attacco Brute Force?

Definizione

Un attacco brute force è un metodo di attacco che consiste nel tentare sistematicamente tutte le possibili combinazioni di credenziali (username e password) fino a trovare quella corretta. È come provare tutte le chiavi di un mazzo fino a trovare quella che apre la porta.

Perché Funziona?

Gli attacchi brute force hanno successo quando:

  • Password deboli: Gli utenti usano password comuni o facilmente indovinabili
  • Nessun rate limiting: Il sistema non limita il numero di tentativi di login
  • Nessun account lockout: Non c'è blocco dell'account dopo tentativi falliti
  • Mancanza di CAPTCHA: Assenza di meccanismi per distinguere umani da bot
  • Feedback dettagliato: Il sistema rivela se l'username esiste o meno

Tipi di Attacchi Brute Force

1

Dictionary Attack

Usa liste di password comuni (wordlists)

2

Credential Stuffing

Usa credenziali rubate da altri data breach

3

Pure Brute Force

Prova tutte le combinazioni possibili

Low Security Vulnerabilità e Sfruttamento

⚠️ Vulnerabilità Principale: Il codice non esegue alcuna sanificazione degli input utente, permettendo attacchi di SQL Injection. Inoltre, non ci sono protezioni contro tentativi multipli di login.

🎯 Metodo 1: SQL Injection Bypass

Il metodo più semplice per bypassare l'autenticazione è sfruttare la mancanza di validazione dell'input SQL.

Payload di Attacco:

Username: admin' OR '1'='1' --
Password: [qualsiasi cosa]

💡 Spiegazione:

Questo payload trasforma la query SQL da:
SELECT * FROM users WHERE username='admin' AND password='...'
in:
SELECT * FROM users WHERE username='admin' OR '1'='1' -- AND password='...'

La condizione '1'='1' è sempre vera, quindi la query restituisce tutti gli utenti. I caratteri -- commentano il resto della query, ignorando la verifica della password.

🎯 Metodo 2: Brute Force con Hydra

Hydra è uno strumento di penetration testing che automatizza gli attacchi brute force su vari protocolli.

Procedura:

  1. Identificare il PHPSESSID nei cookie del browser (Dev Tools → Storage → Cookies)
  2. Identificare il messaggio di errore: "Username and/or password incorrect."
  3. Costruire e eseguire il comando Hydra:
hydra -l admin -P /usr/share/wordlists/rockyou.txt.gz \
   http-get-form \
  "/dvwa/vulnerabilities/brute/:username=^USER^&password=^PASS^&Login=Login:H=Cookie:PHPSESSID=;security=low:F=Username and/or password incorrect."

💡 Risultato:

Password trovata: password

Hydra testa automaticamente tutte le password nella wordlist rockyou.txt fino a trovare quella corretta, identificandola dall'assenza del messaggio di errore nella risposta HTTP.

🎯 Metodo 3: Brute Force con Burp Suite (Singolo Utente)

Burp Suite è un proxy HTTP che permette di intercettare e modificare le richieste web.

Procedura:

  1. Configurare FoxyProxy per intercettare il traffico con Burp Suite
  2. Tentare un login fallito e catturare la richiesta HTTP
  3. Inviare la richiesta a Intruder (tasto destro → Send to Intruder)
  4. In Positions: aggiungere i simboli § solo attorno al parametro password
  5. Selezionare Sniper come Attack Type
  6. In Payloads: scegliere Simple List e caricare una wordlist di password
  7. Avviare l'attacco e analizzare i risultati

💡 Identificare la Password Corretta:

Cercare la richiesta con Content-Length diversa dalle altre. Un login riuscito produce una risposta HTTP con dimensione differente rispetto ai tentativi falliti.

🎯 Metodo 4: Cluster Bomb - Tutti gli Account

Per testare tutte le combinazioni di username e password:

Procedura:

  1. In Positions: aggiungere § sia a username che a password
  2. Selezionare Cluster Bomb come Attack Type
  3. In Payloads:
    • Payload Set 1 (Username): lista di possibili username
    • Payload Set 2 (Password): lista di possibili password
  4. Avviare l'attacco

💡 Credenziali Scoperte:

  • admin : password
  • gordonb : abc123
  • smithy : password
  • pablo : letmein
  • 1337 : charley

Medium Security Protezioni Implementate

🛡️ Nuove Difese: È stata aggiunta la funzione mysql_real_escape_string() che esegue l'escape dei caratteri speciali SQL (come virgolette singole e doppie) aggiungendo backslash prima di essi.

Impatto sugli Attacchi

❌ SQL Injection: Non funziona più perché i caratteri speciali vengono neutralizzati
✅ Hydra: Funziona ancora, basta modificare il cookie in security=medium
✅ Burp Suite: Funziona ancora con le stesse tecniche 

# Hydra con security=medium
hydra -l admin -P /usr/share/wordlists/rockyou.txt.gz \
   http-get-form \
  "/dvwa/vulnerabilities/brute/:username=^USER^&password=^PASS^&Login=Login:H=Cookie:PHPSESSID=;security=medium:F=Username and/or password incorrect."

High Security Protezioni Avanzate

🛡️ Difese Aggiunte:
  • mysql_real_escape_string() per prevenire SQL Injection
  • stripslashes() per rimuovere i backslash aggiunti
  • sleep(3) - Ritardo di 3 secondi ad ogni tentativo di login

Impatto del Rate Limiting

Il comando sleep(3) introduce un ritardo di 3 secondi per ogni tentativo di login. Questo rallenta drasticamente gli attacchi automatizzati:

  • 100 tentativi = 5 minuti
  • 1000 tentativi = 50 minuti
  • 10000 tentativi = 8+ ore

✅ Hydra e Burp Suite funzionano ancora, ma l'attacco diventa estremamente lento e facilmente rilevabile dai sistemi di monitoring.

🛡️ Strategie di Mitigazione

1. Password Policy Robuste

  • Richiedere password di almeno 12 caratteri
  • Combinazione di lettere maiuscole, minuscole, numeri e simboli
  • Impedire l'uso di password comuni o compromesse
  • Implementare l'autenticazione a due fattori (2FA/MFA)

2. Account Lockout & Rate Limiting

  • Account Lockout: Bloccare l'account dopo N tentativi falliti (es. 5)
  • Progressive Delays: Aumentare il delay ad ogni tentativo fallito
  • IP-based Rate Limiting: Limitare i tentativi per IP address
  • Temporary Lockout: Blocco temporaneo crescente (1min, 5min, 30min...)

3. CAPTCHA e Challenge-Response

  • Implementare reCAPTCHA dopo 2-3 tentativi falliti
  • Usare CAPTCHA v3 per analisi del comportamento invisibile
  • Challenge aggiuntive per login da nuovi dispositivi

4. Monitoring e Detection

  • Logging di tutti i tentativi di login (successi e fallimenti)
  • Alert per attività sospette (troppi tentativi, pattern insoliti)
  • Analisi comportamentale (device fingerprinting, geolocation)
  • Integrazione con SIEM per correlazione eventi

5. Difese a Livello di Codice

  • Prepared Statements: Prevenire SQL Injection completamente
  • Password Hashing: Usare bcrypt, Argon2 o PBKDF2
  • Messaggi Generici: "Invalid credentials" invece di "Wrong password"
  • Constant-Time Comparison: Evitare timing attacks

6. Difese Avanzate

  • Passwordless Authentication: Magic links, WebAuthn/FIDO2
  • Risk-Based Authentication: Autenticazione adattiva basata sul rischio
  • Honeypot Accounts: Account dummy per rilevare attacchi
  • WAF (Web Application Firewall): Filtrare traffico sospetto

📌 Riepilogo

Gli attacchi brute force sfruttano la mancanza di protezioni sui meccanismi di autenticazione. La difesa richiede un approccio multi-livello: password robuste, rate limiting, CAPTCHA, monitoring e architetture di autenticazione moderne.

Ricorda: Un'unica difesa non è sufficiente. La sicurezza si ottiene combinando più strati di protezione (defense in depth).
